# Branch workflow

Use the shared branches for Week 1:

- Frontend: `frontend` - header, navigation, static MVP pages, and frontend components
- Backend: `backend` - shared contracts, fixture data, and placeholder procedures
- Integration: `main` - stable branch used to combine reviewed work

## Rules

1. Do not push directly to `main`.
2. Pull the latest approved `main` before starting a new task.
3. Keep frontend work in the `frontend` branch and backend work in the `backend` branch.
4. Contract changes must be reviewed by one frontend and one backend member.
5. Tell the team before renaming or removing a backend procedure or contract field.
6. Run `npm run lint`, `npm run type-check`, and `npm run build` before requesting a merge.

The branch links are maintained in the team message and repository README.
